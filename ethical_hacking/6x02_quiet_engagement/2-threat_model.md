# Threat Model, Lumen Industrial Systems

## Framework Mix
This threat model uses a mixed lens because the engagement spans both technical risk and regulatory consequence. STRIDE is applied to the cloud platform and admin plane where trust boundaries, data exposure, and identity weaknesses are most likely to be structural; MITRE ATT&CK is used where concrete adversary behaviors and exploitation paths matter; and PASTA is used to anchor the most material risks to customer renewal and NIS2 conformity. That mix reflects the actual engagement context: Lumen is not simply an application owner, it is a supplier whose security posture is being evaluated by industrial customers under regulation.

| 1 | Unauthenticated file upload to the public API or admin portal enables remote code execution or web shell persistence. | Public API / admin web application | MITRE-T1190 / STRIDE-T | Critical | Public-facing ingestion paths are a classic initial foothold in industrial SaaS. | 3 | Insecure direct object references or IDORs allow cross-tenant data leakage between customer monitoring environments. | Customer monitoring data store / API endpoints | STRIDE-I / MITRE-T1040 | Critical | Multi-tenant industrial telemetry is highly sensitive. | 4 | Missing or weak session controls permit account takeover through token replay, fixation, or brute-force. | User login and session management | STRIDE-S / MITRE-T1556 | High | Customer and admin accounts are entry points to live monitoring data, and a single stolen session can become a long-lived foothold without raising immediate alarms. |
| 5 | Insecure MQTT or edge-broker broker-to-cloud communications allow spoofed sensor or control messages to reach the platform. | Demo edge gateway / MQTT broker | STRIDE-T / MITRE-T1095 | High | Industrial monitoring depends on trusted telemetry. If edge devices or broker channels are not authenticated and integrity-checked, false operational states can be injected and accepted by the platform. |
| 6 | Overly permissive API authorization allows unauthorised retrieval of historical telemetry or configuration data. | Public API / analytics backend | STRIDE-E / MITRE-T1021 | High | API misuse is a common route to confidential customer data. For industrial SaaS, the impact is greater because the data can reveal operating cadence, vulnerabilities, or process conditions. |
| 7 | Inadequate logging and detection allow attacker activity to remain stealthy for long periods. | SIEM / audit log pipeline / admin activity logs | STRIDE-R / MITRE-T1562 | High | Lumen's NIS2 narrative depends on demonstrable incident detection. If security telemetry is weak or tamperable, the company cannot prove timely response or auditability to industrial customers. |
| 8 | Unencrypted or poorly segmented internal service traffic enables lateral movement from a web tier to backend services. | Internal application services / private network | STRIDE-I / MITRE-T1210 | High | A web compromise should not become a platform-wide takeover. If internal services trust each other without segmentation, a single vulnerable web component becomes a broader platform compromise. |
| 9 | Weak secret storage or hardcoded credentials allow developer or service account compromise. | CI/CD, configuration files, cloud credentials | STRIDE-E / MITRE-T1552 | High | Exposed secrets can be used to pivot into production, deploy malicious changes, or exfiltrate telemetry. This is especially damaging where the platform is used to support regulated industrial customers. |
| 10 | Insecure deserialization or unsafe parsing of uploaded files creates a persistent foothold with downstream exploitability. | File ingestion endpoint / reporting module | MITRE-T1190 / STRIDE-T | High | A polyglot upload issue is practical and business-relevant because it can convert a web boundary into a persistent compromise without user interaction. |
| 11 | Ransomware-style disruption against the analytics platform or backup path impacts customer trust and renewal credibility. | Primary production services / backups | PASTA-Stage-IV / MITRE-T1486 | High | For a SaaS supplier to industrial customers, disruption is more than downtime; it is a failure to maintain NIS2-relevant continuity and evidence of resilience. |
| 12 | Customer-facing diagnostics or misconfiguration leaks deployment metadata, versioning, or system paths enabling targeted follow-on exploitation. | Public web assets / infrastructure metadata | STRIDE-I / MITRE-T1592 | Medium | Even minor metadata leakage can inform attackers about stack composition, runtime versions, and exposed components before a targeted exploit is attempted. |
| 13 | Inadequate rate limiting or abuse controls enable API scraping, credential spraying, or service degradation. | Public API / login endpoints | STRIDE-D / MITRE-T1110 | Medium | Abuse can degrade customer service and create an easy path to account discovery, especially when industrial customers rely on reliable uptime and timely monitoring. |
| 14 | Missing or weak supply-chain control for third-party integrations expands the attack surface beyond the platform boundary. | Partner integrations / external service connectors | PASTA-Stage-IV | Medium | Industrial SaaS often depends on cloud and data partners. Weak controls here matter because a compromise in a connected provider can become a failure in the client's NIS2 conformity story. |

## Prioritisation Note
The top three threats in business-impact terms are the unauthorised file upload or web compromise path, the cross-tenant data exposure path, and the admin/control-plane takeover path. The first matters because it is the most direct route to a customer-impacting compromise in a public-facing SaaS platform. The second matters because it attacks the core trust model of a multi-tenant industrial monitoring platform and threatens customer confidentiality and contractual integrity. The third matters because it compromises the platform as a whole, undermines the reliability narrative behind NIS2 compliance evidence, and could directly affect the three renewal decisions that are tied to this engagement. In other words, the most material risks are not the most exotic ones; they are the ones that convert a technical issue into loss of customer trust, regulatory credibility, and commercial renewal.
